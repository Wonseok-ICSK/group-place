# v0.3.1 (2026-10-23)

소규모 동료 테스트용 그룹 앱. 공개 소스는 main에서 검증하고 비공개 운영 브랜치에 합친 뒤 배포한다.

## 삭제와 3일 보관

삭제 요청은 한 DB 트랜잭션에서 원본·연결 데이터를 `trash_jobs.payload`에 옮기고 활성 표에서 제거한다.
장소·사진·방문·후기·카테고리·월드컵 기록과 마지막 멤버의 방 삭제에 적용된다. 일반 멤버가 나가면서
제거되는 내 후기·빈 방문·월드컵 기록도 보관한다. 보관함은 사용자와 공개 API에서 읽을 수 없다.
사용자에게 복원 버튼을 제공하지 않으며, 필요하면 운영자가 원본 JSON과 백업으로 수동 복구한다.

사진은 경로만 보관하고 실제 파일을 72시간 유지한다. 서버가 10분마다 만료 작업을 받아
**Storage 삭제 성공 → 휴지통 원본 제거** 순서로 처리한다. 실패하면 원본을 유지하고 재시도한다.
lease와 파일 잠금으로 중복 실행을 막고, 서버 중단 후에도 이어서 정리한다. 따라서 정상 상태에서
영구 정리는 삭제 후 72시간부터 약 10분 이내이며, 서버·Storage 장애 시 성공할 때까지 늦어진다.
정리 대기 중인 사진 경로는 다시 등록할 수 없다.

활성 사진만 사용자 Storage 조회를 허용하고 사용자의 직접 DELETE는 막는다. 공개 사진 중계는
요청마다 활성 여부를 확인한다. 이미 받은 이미지와 기존에 발급한 Storage 서명 URL은 만료 전까지
기기 캐시·기존 URL에 남을 수 있다. 공개 목록 서버 캐시는 최대 120초다.

## 자동 백업

- 서버의 `/var/backups/group-place`에 날짜별 DB 덤프와 `place-photos` 실파일을 보관한다.
- 매일 **08:30 / 18:30 Asia/Seoul**. 서버가 꺼졌다면 기동 후 누락분을 한 번 실행한다.
- `public`, `auth`, `storage`, `backup` 스키마를 custom-format pg_dump로 내보내고 pg_restore 목차를 확인한다.
- 사진은 원본·썸네일·휴지통 파일까지 모두 내려받는다. DB·사진 SHA-256과 크기를 manifest에 남긴다.
- 임시 디렉토리에서 완성·검증한 뒤 원자적으로 이름을 바꾼다. 실패 시 이전 완성본을 보존한다.
- 새 백업 성공 후 14일이 지난 완성본을 정리한다. 휴지통에서 영구 삭제된 자료도 백업 보존 기간에는 남는다.
- 결과는 `/var/lib/our-places-jobs/runs.json`에 백업 최근 30건·정리 최근 60건을 저장한다. 비밀번호·원문 오류·사용자 내용은 기록하지 않는다.
- DB 비밀번호는 서버의 root 전용 `/etc/our-places/backup.env`에 숨김 입력으로 저장한다.
  `ssh -t <서버> sudo /usr/local/sbin/group-place-set-db` (또는 릴리스의 `set-db.sh`).
- 백업과 영구 삭제는 같은 잠금을 사용하므로 백업 중 사진이 정리되지 않는다.

이 백업은 프로젝트 전체 복제가 아니다. Supabase 설정·키·역할·함수 확장·외부 서비스 설정은 별도로
관리한다. 다른 프로젝트에 복원할 때는 공식 복원 절차에 따라 역할·Auth/Storage 버전을 맞추고,
사진을 Storage API로 다시 올린다. 같은 디스크의 백업은 그 디스크 고장에 대한 보호가 되지는 않는다.

## 원본 앱 v2.0.0에서 반영

- 장소 추가는 지도 링크부터, 정보 수정은 이름부터 입력한다. 이름·링크 중복을 즉시 알려 주고 기존 장소로 이동할 수 있다.
- 검색 결과가 다른 목록 탭에 있으면 이동 버튼을 보여 준다.
- Android 설치형 앱의 공유 대상으로 지도 링크·문구를 받는다. 데스크톱·iOS 지원 여부는 기기에 따라 다르다.
- 추가 폼은 10분, 메모·후기 초안은 기기에 14일 보관한다. 계정·방·장소·방문별로 나누고 읽기 전용 화면에는 저장하지 않는다.
- 다른 사람이 바꾼 공용 메모·방문 날짜, 다른 기기에서 바뀐 내 후기를 오래된 초안이 조용히 덮지 않도록 확인과 DB 비교를 한다.
- ‘다녀왔어요’ 전환 시 방문 입력칸으로 이동하고, 저장을 눌러야 방문 기록이 남는다고 안내한다.
- 세션 조회 장애 시 다시 시도 화면을 제공한다. 방 5명·계정당 3개 방·공개 방 규칙은 유지한다.

찜은 유지하며 추후 제거 방향이다. 이메일 기반 비밀번호 찾기와 문제 보내기 버튼은 이번 범위에 없다.

## 적용·검증·되돌리기

1. 기존 SQL은 `schema → friends-keepalive → friends-signup → groups → colors → public → stability` 순서다.
2. 운영 DB와 사진의 변경 전 백업을 완료하고 덤프 목차·해시를 확인한다.
3. `supabase/maintenance.sql`을 한 번 실행한다. `maintenance_version()`이 1이어야 한다.
4. 소스를 검토·커밋한 뒤 배포한다. `/readyz` 200, 화면 빌드 `v0.3.1-261023-a73d9`를 확인한다.
5. purge/backup 서비스와 timer의 상태·다음 실행 시각, 첫 백업의 결과를 확인한다.

회귀 검증은 서버 테스트, PGlite에서 SQL 권한·72시간 경계·실패 재시도·경로 재사용 차단,
화면 함수 테스트와 Edge의 예시 데이터로 수행한다. 실제 폰의 공유 대상은 설치된 기기에서 추가 확인한다.

코드는 이전 릴리스로 되돌릴 수 있지만 이전 클라이언트의 직접 삭제는 새 DB 권한에서 거절된다.
SQL까지 되돌리려면 worker timer를 멈추고 **휴지통을 복구하거나 정리를 완료해 비운 후**
`maintenance_rollback.sql`을 실행한다. 비어 있지 않으면 원본 보호를 위해 rollback을 거절한다.
원본 복구 순서는 방 → 멤버·카테고리 → 장소 → 방문 → 후기·사진 → 월드컵이다.
중복 행은 현재 활성 상태를 먼저 확인해 수동 병합한다. 보관함을 강제로 비우는 자동 rollback은 없다.
