# 초기 모델 계획과 결정 사항

작성 2026-10-22. 2인용 원래 앱을 바탕으로 그룹용 초기 모델을 만든다. 원래 앱과 코드·DB·버전을 나눠 따로 빌드하고, 원래 앱의 괜찮은 개선 사항만 이쪽으로 옮겨 온다(반대 방향은 하지 않는다).

현재 앱 기준: **V0.3.1, 소규모 동료 테스트**. 초기 구현 메모는 당시 상태를 기록한 것이며, 현재 변경은 [V0.3.1 릴리스](release-v0.3.1.md)를 따른다.
찜 제거 방향·메일 도입 후 비밀번호 찾기는 [향후 아이디어](future-ideas.md)에 정리한다.

## 결정 사항

### 방(그룹)
1. 방 인원은 **최대 5명**이고, 따로 바꿀 수 없다.
2. 한 사람이 들어갈 수 있는 방은 **3개**까지다.
3. 로그인한 뒤 방을 고르는 화면이 있고, 내 정보(프로필) 화면에서 다른 방으로 넘어갈 수 있다.
4. 방 이름은 만들 때 정한다. 바꾸기는 관리자(방을 만든 사람)만 할 수 있다(우선은).
5. 초대 코드는 첫 멤버가 들어올 때까지 메인 화면에 보이고, 그 뒤로는 설정·내 정보 화면에서 **멤버 모두**가 볼 수 있다.
6. 내보내기, 대표 넘기기는 **없다**. 초대 코드 다시 만들기는 v0.2.0부터 **방장**이 할 수 있다(모든 방, 확인 창, 예전 코드는 바로 못 씀. `docs/public-rooms-design.md` §4.10).
7. 나가기는 내 정보 화면 맨 아래의 별도 버튼으로 한다. 나간 멤버의 **후기는 지운다**(그래야 그 색을 다른 사람이 쓸 수 있다).

### 화면
8. 멤버 색은 **무지개 24색 + 직접 고른 색**이다. 처음 들어오면 그 방에서 아직 안 쓰는 색이 무작위로 정해지고, 나중에 바꿀 수 있다(v0.1.2부터).
9. 후기 칸은 닉네임으로 구분한다.
10. 월드컵은 **황금 도장 기능만 뺀다**. 나머지는 그대로 두고 나중에 다듬는다.

### 가입
11. 가입·참여 시도 제한은 **성공한 시도는 세지 않는다**(같은 Wi-Fi에서 여러 명이 가입해도 막히지 않게).

### 공개 방
12. 방을 만들 때 **공개 방 / 개인 방**을 고르고, 나중에 바꿀 수 없다.
13. 방 선택 화면의 **돋보기 아이콘**으로 공개 방을 검색해 읽기 전용으로 들어갈 수 있다.
14. 공개 방에 참여할 때 "내용(사진·후기 포함)이 공개될 수 있다"는 안내에 동의해야 한다. 공개 방은 사진과 후기도 공개된다.
    v0.2.0의 최종 결정(로그인한 사람만 보기, 찜 비공개·메모 공개, 내 방에 담기 등)은 `docs/ideation-public-rooms.md` 맨 위 표와 `docs/public-rooms-design.md` §0.

### 그 밖
15. 앱(안드로이드)은 웹 MVP를 먼저 만든 뒤에 생각한다. 그동안 개발자 계정을 준비한다.
16. v0.3.1부터 서버 PC에 날짜별 DB·사진 백업을 하루 두 번(08:30 / 18:30 KST) 보관한다. 3일 보관함과 함께 릴리스 문서를 따른다.
17. README에는 실제 사이트 주소를 넣지 않는다.

## 순서

1. **그룹 기능**(1–11): 방 인원·여러 방·방 선택·나가기·색·초대 코드 표시·황금 도장 제거·시도 제한. 한 번의 DB 변경(되돌리기 SQL 포함)과 한 번의 테스트로 같이 낸다.
2. **공개 방**(12–14): 방 만들기 화면의 공개/개인 선택, 공개 방 검색, 읽기 전용 화면, 참여 안내.
3. **이름·배포 정리**: 앱 이름과 문구를 그룹용으로, 서버 서비스·경로 이름을 `group-place`로 옮김.
4. 그 다음: 사진 썸네일(트래픽 줄이기), 계정 삭제, 약관·개인정보 처리방침, 신고, 안드로이드(TWA).

## 구현 메모

- **DB**: 지금 한 사람이 한 방에만 들어가게 막는 것은 `couple_members`의 unique(user_id) 하나다. 이것을 없애고 사람당 3개, 방당 5명 제한을 함수와 트리거로 둔다. 2명 제한은 `join_couple`, `space_code_open`, `join_couple_for` 세 군데에 있다. RLS는 이미 방 단위라 그대로 쓴다.
- **화면**: 지금은 방 하나만 불러온다(`loadAll`의 `.limit(1)`, 방 조건이 없는 조회들). 모든 조회에 현재 방 조건을 붙이고, 늦게 끝난 새로고침이 다른 방 화면을 덮지 않게 한다.
- **색**: `couple_members`에 색 칸을 두고, 방 안에서 겹치지 않게 DB에서 막는다. 나간 멤버의 색은 후기를 지운 뒤 비워진다.
- **나가기**: 나간 사람의 후기와 월드컵 기록을 지우고, 그 사람이 만든 장소·사진은 방에 남긴다. 장소의 `created_by` 같은 칸이 NOT NULL이라 계정 삭제(나중에 Play 출시에 필요)와 함께 정리한다.
- **공개 방**: Supabase의 RLS를 로그인 안 한 사람에게 넓히지 않는다(지금 사진 저장소 정책상 올리기·지우기까지 열린다). 홈 서버가 정해진 항목만 돌려주는 전용 함수로 읽기 전용 화면을 만든다. 공개 방 사진은 Supabase 트래픽(무료 월 5GB)을 많이 쓴다.
- **첫 배포 전 확인**: 이 저장소의 서버 코드는 사이트 주소(`PUBLIC_ORIGIN`)와 아이디 로그인 주소(`LOGIN_ID_DOMAIN`)를 설정 파일에서만 읽는다(코드에 기본값 없음). 지금 서버의 설정 파일에는 `LOGIN_ID_DOMAIN` 줄이 없어서, 이 저장소로 처음 배포할 때 `deploy.ps1 -LoginIdDomain <지금 쓰는 값>`으로 넣어야 한다. 빠뜨리면 새 서버가 설정 오류로 시작하지 않고 이전 릴리스로 되돌아간다.
- **테스트 환경**: Supabase 무료 프로젝트는 계정당 2개라 시험용 프로젝트를 더 만들기 어렵다. 로컬 Supabase(Docker)나, 운영 프로젝트 백업 뒤 시험을 쓴다.

## 검토 요약 (2026-10-22)

| 항목 | 판단 | 비고 |
|---|---|---|
| 방 5명 | 가능 | DB 변경은 작고 화면 손볼 곳이 많음 |
| 여러 방 | 가능 | 5명 기능과 같이 하는 것이 효율적 |
| 안드로이드 | 가능 | Google Play 등록 US$25, 새 개인 계정은 테스터 12명이 14일 비공개 테스트, 계정 삭제·개인정보 처리방침·신고 기능 필요 |
| 공개 방 | 가능, 마지막에 | 개인정보·게시물 관련 의무, 사진 트래픽 |
| 홈 서버 | 지금 규모는 충분 | 먼저 막히는 것은 Supabase 무료 트래픽과 노트북 가동 여부 |

## 빌드 번호

화면(계정 설정 맨 아래)에 보이는 빌드 번호는 `v버전-배포일(YYMMDD)-무작위 5자(16진수)` 형식으로 쓴다. 예: `v0.1.2-261022-081f9`. 배포할 때마다 새로 만든다(무작위 값에 특별한 의미는 없음). 공개 방은 v0.2.0으로 진행한다.
